# Frictions: Notion via the stage chats

One line per friction. Severity: 0 cosmetic, 1 slowed, 2 needed outside help, 3 blocked.

| Stage | What happened | What the chat did | Severity (0 cosmetic, 1 slowed, 2 needed outside help, 3 blocked) | Fixed? |
|---|---|---|---|---|
| Fit (choices) | Only one choice was asked ("Through Composio" vs "Direct Connection"). There is no "Just me" choice: the app assumes a personal prototype. The direct option's label has a trailing space ("Direct Connection "). | Nothing to ask; "Just me" is built in. | 0 | no |
| Fit (what we found) | "Create a database page" is marked "reacts to events" and the Triggers row says "Needs an event trigger when a bug is reported". Wrong: the bug report comes from the agent, not from a Notion event. A first-timer may go looking for Notion webhooks. | — | 1 | no |
| Guide build | The guide was written by gemini-3.5-flash-lite (the cheapest model that had quota), and the first /api/generate call dropped because the guide server was restarted from a terminal at 11:33 (not by the guide itself). The retry worked. | — | 0 | n/a |
| Summary / Register | The summary says "register an internal integration or public OAuth integration", and step 2 says "Choose the integration type (Public or Internal)" without saying which. Only a **public** connection gives a client ID and secret and an OAuth sign-in. Picking Internal (the easier-looking one) dead-ends the whole route. | — | 2 | no |
| Register | The guide sends you to notion.so/profile/integrations and says "New integration". Notion's current docs say Developer portal at app.notion.com/developers/connections → Build → **Public connections** → **Create new connection**, and call them "connections", not "integrations". | — | 1 | unconfirmed (Voj's screen will tell) |
| Register | The guide never mentions **Installation scope** (Any workspace / Selected workspaces only), which is a required field and can't be changed later. | — | 1 | no |
| Register | Notion's docs say the "Authorization URL field populates after a public connection is submitted for review". The guide says no review is needed. If that field is empty, a first-timer has no authorize URL unless someone tells them to build it from client_id, redirect_uri, response_type=code, owner=user. | — | 2 | unconfirmed |
| Callback | The guide never gives the redirect URI to type. Its only example is http://localhost:3000/callback, which is the guide app's own port, not the agent's (4200). Notion matches the URI exactly. | — | 1 | no |
| Page picker | The guide never mentions the page picker on Notion's sign-in screen. Instead, step 5 ("Share database with your integration" via ••• → Connections) comes *before* sign-in. For a public connection, the picker during sign-in is where access is granted. Skip it and sign-in still works, but writes fail with object_not_found. | — | 2 | no |
| Keys | The step "Copy credentials to your project" is owned by "agent", but a human has to copy the secret. The stage itself says "you". | — | 0 | no |
| Prerequisites | "Create a new page in Notion and convert it into a database" doesn't say what properties the bug database needs, or how to find its ID (needed for NOTION_DATABASE_ID). | — | 1 | no |
| Code | The code prompt is one vague sentence. Missing: token exchange with **HTTP Basic** auth, the **Notion-Version** header, storing the refresh token, where to save the token, which port and callback route, and that since 2025-09-03 pages are created under a **data_source_id** (found with GET /v1/databases/:id). | — | 2 | no |
| Paths / open questions | The "open question" says that to let others connect you'd "switch from an internal integration to a public OAuth app". That contradicts the route, which is already a public OAuth app. | — | 0 | no |
| Sources | Every step is marked "verified", but the only source cited is the integrations page itself. No docs link for authorization, page creation or versioning. | — | 1 | no |

| Register (chat) | Asked about Installation scope, it said **Any workspace**. For a just-me prototype **Selected workspaces only** fits better (Any is for Marketplace listing), and the choice can't be changed later. | Gave a confident but questionable answer. | 1 | no |

| Register / Callback (chat) | It ticked the Definition of done ("app shows in developer settings", "redirect URI saved", "scopes set") without me saying I'd done any of it, and invented an app name ("Notion Bug Reporter") that it then used in later stages. | Moved on too early. | 1 | no |
| Callback (chat) | Asked "Is http://localhost OK?", it didn't answer yes or no but gave `http://localhost:4200/callback`. | Callback (chat) | Asked about the guide's "share the database via ••• → Connections" step, it said that's "for the final job stage". It did **not** warn that Notion's sign-in screen has a page picker where the database must be picked. No warning about the page picker anywhere before sign-in. | Deferred, no warning. | 2 | no |
| Keys (chat) | It said the Client ID is "on the main page" and the secret is the "**Internal Integration Secret**" on a **Secrets** tab. The internal secret is a different credential and won't work for the token exchange. | Wrong labels. | 2 | unconfirmed (Voj's screen will tell) |
| Keys (chat) | When asked which .env, it correctly said test-agent-notion/.env and not the guide app's. It never said not to paste the secret in chat. | Answered correctly. | 0 | n/a |
| Code (chat) | The coding prompt is one generic sentence ("handles the Notion OAuth flow, stores the access token securely, and calls the Notion API…"). It doesn't name the files (server.js routes, tools/index.js), the token file connections.js checks (.notion-token.json), NOTION_DATABASE_ID, or the property name of the title column. I had to work all of that out from this folder. | Gave the prompt. | 1 | no |
| Code (chat) | Asked for API details, it said to send client_id and client_secret **in the JSON body**. Notion's docs say **HTTP Basic** (base64 of id:secret). I wrote the code to try the chat's way first and fall back to Basic, logging which one worked (see the sign-in row). | Wrong per docs. | 2 | unconfirmed until sign-in |
| Code (chat) | It said `Notion-Version: 2022-06-28` and a `database_id` parent. That still works for a database with one data source, but it's two versions behind (2025-09-03 moved page creation to `data_source_id`; latest is 2026-03-11) and breaks if someone adds a second data source to the database. I followed it. | Outdated. | 1 | no |
| Code (chat) | It said to store the token "in the local .env file or local storage". Putting an OAuth token in .env (or browser storage) is poor practice and doesn't match the agent's check (.notion-token.json). It never mentioned the **refresh_token** Notion returns, so nothing refreshes the token. I stored the whole token response in .notion-token.json (mode 600). | Wrong / incomplete. | 1 | no |
| Code (chat) | It never mentioned `owner=user` and `response_type=code` on the authorize URL, or a `state` value. `owner=user` is Notion-specific and required. I added all three. | Missing. | 1 | no |
| Code (chat) | After my report it ticked both Definition-of-done items even though I said the keys check still fails, and it asked for a NOTION_REDIRECT_URI in .env that nothing reads. | Moved on too early. | 0 | no |
| Connect (chat) | The opening turn said to open **http://localhost:4200/signin**. I'd told it the route is /login, so that URL 404s. Its page-picker hint is a single clause ("select your bug database's workspace page and click Allow access"). It doesn't say the picker decides what the agent can write to, or that skipping it leads to object_not_found. That's the first and only mention of the picker. | Wrong URL, weak warning. | 1 | no |
